\section{Technologies and System Architecture}

This section describes the technical foundation of the \projectTitle{} system, detailing the chosen technology stack, the high-level system architecture, and the communication protocols between components.

\subsection{Technology Stack}

The system is built using modern, industry-standard technologies to ensure scalability, security, and developer productivity. The stack is divided into three primary layers:

\begin{itemize}
    \item \textbf{Backend:} 
    \begin{itemize}
        \item \textbf{Python 3.12:} The core programming language.
        \item \textbf{FastAPI:} A modern, high-performance web framework for building APIs with Python based on standard Python type hints.
        \item \textbf{SQLAlchemy:} An SQL toolkit and Object-Relational Mapper (ORM) that provides a full suite of well-known enterprise-level persistence patterns.
        \item \textbf{Alembic:} A lightweight database migration tool for usage with SQLAlchemy.
        \item \textbf{Argon2id:} Used for secure password hashing via the Passlib library.
    \end{itemize}
    
    \item \textbf{Frontend:}
    \begin{itemize}
        \item \textbf{React:} A JavaScript library for building user interfaces.
        \item \textbf{Vite:} A build tool that provides a faster and leaner development experience for modern web projects.
    \end{itemize}

    \item \textbf{Data \& Infrastructure:}
    \begin{itemize}
        \item \textbf{PostgreSQL:} A powerful, open-source object-relational database system.
        \item \textbf{Docker \& Docker Compose:} Used for containerization and orchestration of the various services to ensure environment consistency.
    \end{itemize}
\end{itemize}

\subsubsection{Containerization}
The application is managed using \texttt{docker-compose.yml}, which defines three services:
\begin{enumerate}
    \item \textbf{Frontend:} Serves the React single-page application (SPA).
    \item \textbf{Backend:} Runs the FastAPI server, handling business logic and API requests.
    \item \textbf{DB:} A PostgreSQL instance that persists all system data.
\end{enumerate}

\subsection{Authentication and Security}

The system implements \textbf{JWT (JSON Web Token)} Bearer authentication.
\begin{itemize}
    \item \textbf{Identity Management:} When a user logs in, the backend validates credentials using Argon2id hashing.
    \item \textbf{Token Issuance:} Upon successful validation, the server issues a JWT signed with a \texttt{SECRET\_KEY}.
    \item \textbf{Authorization:} Subsequent requests include the token in the \texttt{Authorization} header. The backend uses FastAPI Dependency Injection to verify roles (Customer vs. Admin).
\end{itemize}

\subsection{Database Persistence and Migrations}

Data integrity is managed through SQLAlchemy models. To handle evolution of the data schema without data loss, \textbf{Alembic} is used for migrations.

\begin{lstlisting}[style=pythonstyle, caption=Example of a Database Migration Command]
# Applying migrations to the database
docker compose exec backend alembic upgrade head
\end{lstlisting}

The system also includes a deterministic seeding script (\texttt{seed.py}) that populates the database with 12 locations, 50 cars, and 100 customers, ensuring a consistent testing environment across different developer machines.

\subsection{API Design}

The API is designed following \textbf{RESTful principles}. It provides separated endpoints for public, customer, and administrative access.

\begin{itemize}
    \item \textbf{Public:} Login and registration.
    \item \textbf{Customer:} Managing profile, booking rentals, and downloading invoices.
    \item \textbf{Admin:} Full CRUD (Create, Read, Update, Delete) operations on fleet, customers, and discount codes.
\end{itemize}

Documentation is automatically generated via \textbf{Swagger UI}, available at the \texttt{/docs} endpoint of the backend service.
